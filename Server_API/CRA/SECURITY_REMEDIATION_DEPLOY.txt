Deployment behavior
- The authentication credential is now a server-managed Secure, HttpOnly
  session cookie. Existing pre-migration bearer sessions are intentionally
  invalidated; users will need to sign in again after deployment.
- Authenticated write requests are protected with a per-session CSRF token.
- Logout invalidates only the active server session; other independent user
  sessions remain valid.
- Role/status/password lifecycle changes revoke affected server sessions.
- /api/server/status is ADMIN-only and is consumed by Administration -> System.
- Stock permissions follow the approved role matrix.
- Servicing and Call Out drafts/reports require a valid PNG technician
  signature. Legacy unsigned/malformed drafts cannot generate reports.
- Formal Section Reports stage DOCX/PDF output and publish only after the
  complete set succeeds.
- Upload validation now verifies supported image content and dimensions.
- No new npm dependency was added.

Frontend deployment coupling
- Do not deploy the cookie-session frontend against the old bearer-token
  backend; login and authenticated actions would fail.
- Production source maps are disabled by Web_UI/scripts/build-github.js.
- The frontend CSP is delivered by meta on GitHub Pages. GitHub Pages cannot
  emit the agreed frame-ancestors/X-Frame-Options response headers, so the
  code includes a client-side frame-deny fallback. Full C-08 header compliance
  still requires a frontend custom domain/proxy where response headers can be
  controlled (for example through Cloudflare).

Cloudflare-bound controls
- The final Maintenix site will run behind Cloudflare.
- Do not create temporary DEV systemd units, local reverse-proxy/header daemons,
  scheduled jobs, or other persistent services solely to reproduce controls that
  belong to the final Cloudflare edge.
- Current application-side hardening should be tested as-is on DEV.
- Final HTTP response-header enforcement (including CSP frame-ancestors 'none',
  X-Frame-Options: DENY, HSTS/edge TLS policy, and final proxy/header rules) is
  a migration requirement and must be validated on the Cloudflare-hosted
  candidate.
- This does not change the required Maintenix application processes managed by
  startAll.js.

48-hour offline/session update — 2026-10-19
- CRA server session policy is now a 48-hour inactivity/validation window.
- Successful authenticated profile/auth validation refreshes the Secure HttpOnly
  session cookie for another 48 hours. Automatic frontend synchronization performs
  this validation while connectivity is available.
- The API now issues a signed RS256 offline lease valid for 48 hours. The lease is
  for local browser workflow authorization only; it is never accepted as an API
  credential and does not bypass cookie session, CSRF, role/status or ownership checks.
- Runtime signing keys are generated on first use at:
    data/offline-lease-private.pem
    data/offline-lease-public.pem
  unless OFFLINE_LEASE_PRIVATE_KEY_FILE / OFFLINE_LEASE_PUBLIC_KEY_FILE override them.
- The API service account must be able to create/write the configured key directory.
- Do not commit or copy the DEV signing keypair into LIVE. LIVE must use its own pair.
- Preserve a LIVE pair after leases have been issued so ordinary redeployments do not
  invalidate still-valid local leases.
- New backend source file required:
    Server_API/CRA/lib/offlineLease.js
- Matching modified backend files:
    Server_API/CRA/lib/sessions.js
    Server_API/CRA/lib/profileRoutes.js
    Server_API/CRA/routes/auth.js
- Matching frontend is already designed to verify the local lease and synchronize
  reference data/drafts automatically. Backend and frontend must be treated as a
  coordinated release for offline acceptance.

Targeted DEV validation after install/restart:
1. Login online and confirm Secure/HttpOnly cookie plus a 48-hour expiresAt.
2. Confirm /api/profile/me returns offlineLease with a ~48-hour expiresAt.
3. Stay online and confirm a later profile/automatic sync renews the session/lease window.
4. Load Servicing, Call Out and (ADMIN) Section Reports online once.
5. Disconnect network and confirm those workflows can start from synchronized local data.
6. Save a local draft offline, reconnect, and confirm automatic server sync.
7. Confirm Add Area and final report generation remain blocked offline.
8. Confirm an expired/tampered local lease cannot authorize offline protected routes.
9. Confirm logout/account/password/role lifecycle controls still revoke server sessions.
