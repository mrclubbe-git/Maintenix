WHAT CHANGED
------------
The notification system now uses:
- a central event registry;
- a central notification service;
- locked/atomic notification persistence;
- idempotency keys to suppress duplicate event notifications;
- a persistent notification delivery outbox;
- a dedicated notification delivery worker;
- Web Push retries and delivery diagnostics;
- consistent Planner acknowledgement behavior;
- completion/failure notifications for Servicing, Call Out, and Formal Reporting.

The long-running CRA stack is now:
1. API server — index.js
2. Servicing worker — servicingWorker.js
3. Call Out worker — calloutWorker.js
4. Notification delivery worker — notificationWorker.js

All four are launched by:
  npm run start:all

RUNTIME FILE
------------
The notification delivery worker creates/uses:
  data/notification-delivery.json

This is runtime state and must not be committed to GitHub.
