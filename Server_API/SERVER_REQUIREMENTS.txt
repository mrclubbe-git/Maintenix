MAINTENIX SERVER REQUIREMENTS
=============================

Purpose
-------
This document describes the server-side requirements for the Maintenix development
environment when the Web UI is hosted on GitHub Pages and Server_API runs on a
separate Linux server.

Current development Web UI:
    https://mrclubbe-git.github.io/Maintenix/

Current development API origin:
    https://dev-api.main-tenix.com

Current public API health check:
    https://dev-api.main-tenix.com/api/health

The development API is exposed over HTTPS through Cloudflare Tunnel and is intended
for development/testing with synthetic data.


1. OPERATING SYSTEM
-------------------
Required:
- Linux server.
- 64-bit installation recommended.
- Normal command-line access.
- Git installed.
- curl installed for health checks.

Linux is required for the complete current feature set because the server-status
endpoint reads /proc/stat and uses the Linux "df -P" command.


2. NODE.JS AND NPM
------------------
Required:
- Node.js 18 or newer.
- npm.

Recommendation:
- Use a currently maintained Node.js LTS release.

The current Server_API dependency tree includes packages requiring Node.js >= 18.


3. APPLICATION FILES
--------------------
The server needs a checked-out copy of the Maintenix repository, specifically:
    Maintenix/Server_API

Typical installation:
    git clone https://github.com/mrclubbe-git/Maintenix.git
    cd Maintenix/Server_API
    npm ci

For an existing installation:
    cd Maintenix
    git pull
    cd Server_API
    npm ci


4. REQUIRED SERVER PROCESSES
----------------------------
Three server-side processes are required:

1. API server
   - index.js

2. Servicing worker
   - servicingWorker.js

3. Call-out worker
   - calloutWorker.js

Start all three with:
    npm run start:all

Do not intentionally run duplicate worker instances unless the queue-processing
behaviour has first been designed and tested for multiple workers.


5. INTERNAL API PORT
--------------------
Default internal API port:
    5055

The API listens on:
    0.0.0.0:5055

The port can be overridden with the PORT environment variable, for example:
    PORT=5056 npm run start:all

For the current development deployment, the browser should use the HTTPS Cloudflare
Tunnel hostname rather than connecting directly to port 5055.


6. DEVELOPMENT HTTPS ENDPOINT
-----------------------------
Current browser-accessible API origin:
    https://dev-api.main-tenix.com

Requirements:
- HTTPS must remain valid and browser trusted.
- Requests for /api/* and /uploads/* must reach the Maintenix Server_API service.
- The Cloudflare Tunnel must route the development hostname to the Server_API
  service listening on the Linux server.
- The origin service must remain reachable by the Cloudflare Tunnel connector.

Do not add a trailing slash or "/api" to the configured API base URL. The Web UI
already requests paths such as /api/auth, /api/reports and /uploads/....


7. CLOUDFLARE TUNNEL
--------------------
The current development API uses Cloudflare Tunnel for HTTPS browser access.

The tunnel configuration must publish:
    dev-api.main-tenix.com

and route that hostname to the Maintenix API origin service, normally:
    http://127.0.0.1:5055

or the equivalent local address used by the tunnel connector.

The Node.js API itself does not need to terminate public TLS when Cloudflare Tunnel
is providing the HTTPS edge connection.


8. FIREWALL / NETWORK ACCESS
----------------------------
With Cloudflare Tunnel, direct public exposure of TCP 5055 is not required and is
not recommended.

Recommended:
- Keep TCP 5055 restricted to the local server/private network as appropriate.
- Permit the Cloudflare Tunnel connector to make its required outbound connections.
- Restrict SSH administration to trusted sources where practical.

If the deployment model changes away from Cloudflare Tunnel, review firewall and
TLS requirements before exposing the API directly.


9. CORS
-------
The browser origin that must be allowed is:
    https://mrclubbe-git.github.io

The current Maintenix Server_API includes this origin in its default CORS allow-list.

If the UI later moves to another hostname, configure CORS_ORIGINS accordingly.
Example:
    CORS_ORIGINS=https://mrclubbe-git.github.io,https://app.example.com

Only origins that genuinely require browser access should be allowed.


10. PERSISTENT AND WRITABLE DATA
--------------------------------
The application uses files below:
    Server_API/data/

The account running Maintenix must have read/write access to the application data
that the API and workers update.

This includes generated/uploaded content, templates and the current file-based JSON
application data.

Important:
- Preserve Server_API/data during updates.
- Preserve the template files used by report/document generation.
- Ensure Server_API/data/uploads and generated subdirectories are writable.
- Do not run the application from a read-only filesystem.

The current development API uses synthetic data, but the same persistence rules
still apply to preserve a stable test environment.


11. BACKUPS
-----------
Back up at minimum:
    Server_API/data/

Recommended:
- Automated backups.
- Multiple backup generations.
- At least one backup copy outside the application server.
- Periodic restore testing.


12. SERVICE ACCOUNT
-------------------
Recommended:
- Run Maintenix under a dedicated non-root Linux user.
- Give that service account the required access to Server_API/data.
- Do not run the Node.js application as root unless there is a specific operational
  requirement.


13. PROCESS SUPERVISION
-----------------------
For anything beyond a temporary terminal test, use systemd or another suitable
process supervisor.

The supervisor should:
- Start Maintenix automatically after reboot.
- Run:
      npm run start:all
- Restart the stack if it exits unexpectedly.
- Capture stdout/stderr logs.
- Run as the dedicated Maintenix service account.
- Use Server_API as its working directory.

The Cloudflare Tunnel connector should also be configured to start automatically
and remain supervised on the server.


14. REQUEST SIZE / UPLOADS
--------------------------
The API currently accepts JSON/form request bodies up to 25 MB.

Any intermediary between the browser and Node.js, including tunnel/proxy policy,
must not impose a lower request-body limit for features that require these uploads.


15. GITHUB PAGES API CONFIGURATION
----------------------------------
The GitHub repository Actions variable should be:
    MAINTENIX_API_BASE_URL=https://dev-api.main-tenix.com

The Web UI build reads this value and uses it as the base for API and uploaded-file
requests.

Use the origin only:
    https://dev-api.main-tenix.com

Do not use:
    https://dev-api.main-tenix.com/
    https://dev-api.main-tenix.com/api

After changing MAINTENIX_API_BASE_URL, rebuild/redeploy the deploy branch so the
compiled GitHub Pages UI receives the new value.

The project workflow and GitHub build script also use the same development API as
their hosted-build fallback when MAINTENIX_API_BASE_URL is not defined.


16. HEALTH CHECK
----------------
The API provides:
    GET /api/health

Expected response:
    {"ok":true}

Local origin test:
    curl http://127.0.0.1:5055/api/health

Public development test:
    curl https://dev-api.main-tenix.com/api/health

A successful public health check confirms that HTTPS/Tunnel routing reaches a
responding API process.


17. SERVER STATUS CHECK
-----------------------
The API also exposes:
    GET /api/server/status

On Linux this uses:
- /proc/stat for CPU usage.
- df -P for filesystem statistics.

This endpoint is useful for validating the Linux-specific system-monitoring path.


18. DEVELOPMENT TEST ACCEPTANCE CHECKLIST
-----------------------------------------
[ ] Linux server is running.
[ ] Node.js 18+ and npm are installed.
[ ] Maintenix repository is checked out and current.
[ ] npm ci completes successfully inside Server_API.
[ ] npm run start:all starts without errors.
[ ] API, servicing worker and call-out worker are all running.
[ ] http://127.0.0.1:5055/api/health returns {"ok":true}.
[ ] Server_API/data is writable by the service account.
[ ] Persistent test data is backed up as required.
[ ] Cloudflare Tunnel is running and supervised.
[ ] dev-api.main-tenix.com routes to the Maintenix API.
[ ] https://dev-api.main-tenix.com/api/health returns {"ok":true}.
[ ] GitHub Pages origin https://mrclubbe-git.github.io is allowed by CORS.
[ ] MAINTENIX_API_BASE_URL is https://dev-api.main-tenix.com.
[ ] The deploy branch has been rebuilt after API configuration changes.
[ ] Login and normal API operations work from the GitHub Pages Web UI.
[ ] /uploads resources referenced by the application load through the HTTPS API
    origin.


19. CURRENT START COMMAND
-------------------------
Development server stack:
    cd /path/to/Maintenix/Server_API
    npm ci
    npm run start:all

This starts the API plus both background workers.


SUMMARY
-------
Current development browser path:
    GitHub Pages Web UI
        -> https://dev-api.main-tenix.com
        -> Cloudflare Tunnel
        -> Maintenix Server_API on Linux (default port 5055)

Key requirements are Linux, Node.js 18+, all three Maintenix server processes,
persistent writable Server_API/data, the Cloudflare Tunnel, CORS access for the
GitHub Pages origin, and MAINTENIX_API_BASE_URL set to the development HTTPS origin.
