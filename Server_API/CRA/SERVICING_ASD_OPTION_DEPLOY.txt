CRA SERVICING ASD OPTION - DEV DEPLOYMENT
==========================================

Purpose
-------
Add an explicit ASD-installed choice for Substation servicing sessions using NFPA 72.
When the technician selects No, ASD-specific checklist questions are excluded from:
- the active servicing checklist;
- the saved servicing draft snapshot;
- the queued generation payload; and
- generated servicing report rows.

Frontend
--------
The Web UI change is deployed separately through GitHub Pages.

Backend files to copy from this package into:
  /home/charl/projects/maintenix-dev-api/Server_API/CRA/

Copy these exact paths:
  lib/servicingFeatures.js
  lib/servicingGenerator.js
  data/templates/full_manual_checklist_questions.json

Do not replace runtime data files, uploads, users, sessions, queues, statuses,
drafts, notifications, area metadata or any other data/ runtime folder content.

Restart
-------
Because lib/servicingGenerator.js loads the new servicingFeatures module,
restart ONLY:
  maintenix-dev-api.service

Validation target
-----------------
We are checking four boundaries:

1. Checklist source:
   GET /CRA/api/servicing/checklist?type=substation
   The six NFPA 72 ASD questions should carry:
     "requiresFeature": "ASD"

2. Web workflow:
   Substation + NFPA 72 must ask "ASD installed?"
   - Yes: ASD questions remain in the checklist.
   - No: ASD questions are absent.

3. Draft:
   A session saved with ASD = No must have no ASD question rows in its
   questionRowsSnapshot.

4. Generation:
   Generate the ASD = No draft and confirm the final servicing report has no
   ASD checklist rows.
   The server generator also filters ASD responses when asdInstalled is false.

Backward compatibility
----------------------
Older servicing drafts that do not contain asdInstalled keep their historical
question set. Older snapshots without requiresFeature metadata are recognized
using the existing "ASD" question wording.
